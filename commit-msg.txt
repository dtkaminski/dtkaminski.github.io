Tokenise the business-event modal's shadow and control radii

Two hardcoded values left in BizEventModal, both dark-theme residue sitting next to the
--surface-1 fallback fixed in 0e9dafc.

box-shadow was 0 20px 60px rgba(0,0,0,0.5) — a 50%-opacity black cast 60px under a white
dialog, which is a shadow drawn for a near-black surface. Now --shadow-raised, the token
for elevated content: two layers at 14% and 5% of the ink colour rather than one heavy
black one. --shadow-panel would have been wrong, and is what I first suggested: that one
is a 1px hairline for flat panels, and a dialog floating over a scrim is raised.

border-radius was a literal 6 on all seven controls — the select, four inputs and both
buttons. CLAUDE.md puts buttons and inputs on --radius-md, which is 5px. The panel keeps
var(--r-lg), which maps to --radius-none, so containers stay square.

Scoped by finding the modal's own opening and closing lines rather than a line number.
The first attempt used start+30 and picked up a borderRadius:6 from the next component;
the assertion caught it and nothing was written. borderRadius:6 appears elsewhere in this
file and is deliberately untouched.

Rendered and measured, not assumed: panel rgb(255,255,255), radius 0px, shadow resolving
to rgba(22,21,15,0.14) 0 8px 24px -6px plus rgba(22,21,15,0.05) 0 2px 6px, and all four
control types at 5px. Containers square, controls --radius-md — the rule, both halves.

Note for whoever is in this file next: it is LF now, not CRLF. It changed under me
mid-edit and a script assuming CRLF split it into one line and aborted.
