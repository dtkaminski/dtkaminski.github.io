Give 800 its own step instead of rounding it to bold

The previous commit collapsed nine numeric font weights onto four tokens, which meant
24 elements set to 800 started rendering at 700. That was the one value change in an
otherwise mechanical rename, and it did not need to be: 800 was a real step being used
deliberately, not a stray.

So --weight-heavy: 800 is added and those 24 sites now reference it.

Identifying them had to be positional, not textual. By the time the sweep landed all of
them said var(--weight-bold), indistinguishable from the 163 that were genuinely 700,
and 18 lines in the file carry more than one fontWeight. So the 24 were recovered by
mapping 80828e8 (the last commit before the sweep) line by line against the current
file -- both are exactly 15,752 lines -- pairing the nth numeric weight on each old line
with the nth token on the new one, and rewriting only where the old value was 800 and
the new token was bold. All 24 matched that shape; none was already something else.

Verified by resolving every token back to its number and diffing against the
pre-sweep file. 398 of 423 sites are now exact, including all 24 at 800. The only
remaining deltas are the four genuine strays -- one 450 and five 550 to 500, eighteen
650 to 600, one 750 to 700 -- which stay rounded, because a weight scale with nine steps
reached by nudging single components is the debt the tokens exist to remove.

One site is untouched and still hardcoded: line 1766 is fontWeight:bold?700:400, a
ternary on a local variable rather than a literal, so it needs a small refactor rather
than a substitution.
