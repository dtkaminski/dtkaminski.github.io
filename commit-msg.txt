One action, one Mark done

The Today page rendered the top action twice. Greta's own hero has Start and Mark
done; the nested "Channels, stock and track record" panel is the marketing-os Today
component, which renders its own "do this first" with the same action and its own
pair of buttons. The two did not share state — V3Done sets a local topDone, the
embed's act() reloads only itself — so closing the action in one place left the
other still offering to close it, and a person who used both wrote two action_done
rows for one closed action.

Not an instrumentation double-fire, which is what I went looking for: greta-app.js
has exactly one track('action_done') call site and the embed bundle has exactly
one, they reach the server by different paths (actionVerb's direct fetch vs the
embed's fetcher), neither calls the other, and nothing writes product_events
server-side. Two buttons, not two events per click. But two buttons for one action
is still wrong, and the hero belongs upstairs where the page already put it.

So mosView takes an extra-props argument and Today is mounted with
{ hideHero: true }, which drops the panel's "do this first" block. The abstention
and nothing-open notices stay: they only render when there is no top action, and
nothing above them explains why the read is silent.

The owner-today nav destination still calls mosView('Today') bare, so the
standalone screen keeps its hero.

Verified: both bundles rebuild byte-identical from source at this HEAD, node --check
passes, and the compiled guard is !(e.hideHero&&T)&&Fragment — the branch is gated,
not removed. today-calendar.build.js cache-bust bumped to 20260930b; build-app.mjs
does not touch that one and a returning visitor would have kept the stale embed.
