Tokenise the eleven computed font weights

I reported one hardcoded weight left in greta-app.jsx, at line 1766. There were
eleven. The scan that found it matched `fontWeight:` followed by a literal or the words
bold/normal, and line 1766 is `fontWeight:bold?700:400` — it showed up only because the
prop controlling it happens to be called `bold`. Every other computed weight, written
`isRollup ? 600 : 400` or `hot||cold?700:400`, has a condition where the literal sits
and was invisible to that pattern. The correct scan is every `fontWeight:` whose value
contains a digit anywhere.

All eleven now use tokens on both branches:

  1766  bold              700/400 -> bold/normal
  5852  big               700/500 -> bold/medium
  5854  big               700/500 -> bold/medium
  7528  isRollup          600/400 -> semi/normal
  8884  hot||cold         700/400 -> bold/normal
  11019 t.isNow||t.late   700/400 -> bold/normal
  11429 x===tf            600/400 -> semi/normal
  12229 on                600/400 -> semi/normal
  12289 hi                600/400 -> semi/normal
  13721 hi                700/500 -> bold/medium
  13840 isCur             700/400 -> bold/normal

Exact, every one: each number maps to the token holding that same value, so nothing
renders differently. The regex stops the condition at a comma, brace or colon so it
cannot run past the property it belongs to, and the eleven replacements were asserted
rather than assumed.

greta-app.jsx now has no numeric font weight anywhere — verified with the prefix-safe
scan, which is what the earlier check should have been. The minified bundle keeps all
eleven ternaries with tokens on both arms.
